# 博客语言优化

## 总原则

+ **只做语言优化，不重写题解思路**。优化目标是让原文更清晰、自然、简洁，而不是替作者补全另一套证明、动机或实现细节。
+ **忠于原文含义**。不得把原文中的说法改成相近但含义不同的表述；尤其是结论、因果关系、更新对象、统计对象、复杂度来源等关键语义，必须保持一致。
+ **不凭空补充内容**。不要添加原文没有提到的推导、性质、实现技巧、边界处理、正确性说明或复杂度解释，即使这些内容看起来是正确的。
+ **不添加空泛废话**。避免加入“需要避免重复统计”“这样可以保证正确性”“显然可得”“容易发现”等没有承担具体信息量的句子，除非原文已经表达了同样意思。
+ **保留作者的表达重心**。如果原文重点是“如何更新答案”，不要改成“如何判断合法区间”；如果原文重点是“枚举出现位置”，不要扩写成完整的区间归类证明。

## 允许修改的内容

+ **优化语言表达**。如果表述冗杂、含糊或不够准确，可以在不改变原意的前提下改写为更清楚的句子。
+ **规范公式与符号**。将随意书写的公式整理为 Markdown 和 LaTeX 格式，统一变量、下标、区间写法和求和符号。
+ **统一标点格式**。正文使用中文标点；英文、代码、文件名和公式中的符号按语境保留。
+ **修正低级笔误**。可以直接修正错别字、明显漏字、格式错误和 Markdown 链接问题。
+ **压缩冗余背景**。可以删去与题解无关的冗余背景，但不能删掉必要条件、结论和逻辑关系。

## 禁止修改的内容

+ **禁止替作者补证明**。原文没有展开的正确性证明、分类讨论、双重求和展开、复杂度摊还细节，不要主动补上。
+ **禁止改变技术含义**。不要把“更新答案”改成“判断合法性”，不要把“统计贡献”改成“避免重复统计”，不要把“可以维护”改成更强的结论。
+ **禁止擅自引入新概念**。不要新增原文未使用的定义、记号、算法名、数据结构或归纳方式。
+ **禁止过度解释共识内容**。对熟悉算法竞赛的读者默认成立的常识，不需要展开成教学式说明。
+ **禁止为了顺滑而改掉精确性**。如果一句话虽然不够文艺但技术含义准确，应优先保留准确性。

## 不确定时的处理

+ **先保留，再标注疑问**。如果某处涉及严重的逻辑、数学或代码含义不确定，不要直接改成自己猜测的版本，应保留原意并标注需要确认的疑点。
+ **最小化改动范围**。每次修改只处理当前句子或段落暴露的问题，不顺手重构整篇文章。
+ **保留可追溯性**。如果需要大幅调整段落顺序或删减内容，应能说明对应的原文依据。

## 题干信息展示

+ 删除冗余背景与叙述，保留题目最本质的数学结构，并注明必要的数据范围；通常不需要保留样例。
+ 尽量将题干和数据范围整理为一段话，不必拆成多个小节，使题面保持简洁。但如果合并会导致条件遗漏或阅读困难，应优先保证信息完整、逻辑清晰。
